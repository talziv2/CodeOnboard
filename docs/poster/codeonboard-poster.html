01 The problem

Documentation is missing, stale, or written for someone who already knows the system. A README rarely says where to start reading for the specific thing you care about.

  • Developers lose days clicking through files, building an incomplete mental map.
  • Skimmed code produces false confidence — the most expensive failure mode.
  • AI assistants (Copilot, Cursor, Claude) are reactive and stateless: they answer the question in front of them but hold no model of what you have learned.
  • In the AI-assisted era the bottleneck moved from writing the line to understanding, validating and critiquing what was produced.

02 The idea

One graph serves as both the system's teaching plan and the user's progress record. Storing them as the same object is the project's distinctive contribution.

  • Every node is one teachable concept, anchored to a real (file, line_start, line_end).
  • Every node carries an on-demand lesson and a tracked understanding state.
  • The path reshapes at runtime: confusion splices in a foundational prerequisite.
  • The graph persists — you return to your graph, not to a fresh chat.
Positioning
Frontier chat tools will always out-analyse this system on raw code. They will not hold a persistent, repo-anchored model of what this developer has internalized about this codebase. That artifact is what onboarding actually needs.

03 System architecture — nine agents, one shared state object

A LangGraph state machine runs the one-off analysis pipeline; the interactive loop calls agents directly. Agents communicate only through OnboardState — no globals, no cross-agent imports. Every agent degrades gracefully: failures append to state.errors and never raise.

Cheap by default, smart rarely
Eight of nine agents run on Claude Haiku; Sonnet is reserved for the two genuine multi-step reasoning tasks — curriculum synthesis and foundational-concept inference. Sonnet is never used in a loop. Embeddings run locally, so retrieval costs nothing per query, and a repeated commit is re-analysed for free.
Grounding is the hallucination guard
Every node anchor must resolve to a chunk that was actually retrieved. The Mentor retries on duplicate anchors and on invented file paths; the Mutator refuses to splice an ungrounded node rather than teaching a lie. Edge kind is pinned to Literal["sequence"] at the wire format, so the initial graph is provably a chain.

04 How a session runs

Two halves with deliberately different lifecycles: a throwaway interview that produces a structured goal, and a durable learning session that may span days.

  • Interview — four core questions plus 1–2 follow-ups conditional on goal type; one Haiku call synthesizes the goal JSON.
  • Start — same repo and identical goal resumes from SQLite; otherwise the pipeline runs once and the graph is persisted.
  • Loop — render lesson → answer → grade → advance, with free navigation to any node in the graph.
  • Override — the user can overrule the Grader at any time: mark_understood, mark_weak, skip. It is their graph.
## interactive session API POST /session/start → run or resume GET /session/{id}/lesson POST /session/{id}/respond → grade + mutate POST /session/{id}/advance POST /session/{id}/jump POST /session/{id}/override GET /session/{id}/file → sandboxed source

The Next.js client renders the graph as the centrepiece, with a lesson panel and a source viewer scrolled to the node's exact line range.

05 The learning graph

The Mentor emits 5–8 nodes (4–10 depending on requested depth) plus exactly N−1 sequence edges. Each node is a concept, an anchor, and a piece of mutable state.

08 The adaptive inner loop

Each iteration is one predict-then-reveal question. The Mutator is the only step permitted to change graph structure — and it is the moment "adaptive" stops being a marketing word.

09 Structural adaptation

On confused, the Mutator retrieves candidate chunks excluding existing anchors, asks Sonnet for a more foundational node, verifies the anchor is real, and reroutes the chain. At most one prerequisite per node — the system makes one focused attempt to unblock you, then gets out of the way.

weak_spot is sticky: it survives later mastery as a permanent record of a rough patch, and feeds the resume heuristic.

A rollback worth reporting
The Mentor was briefly allowed to emit prerequisite edges in the initial graph. It worked — and was then deliberately reverted after architectural review. Prerequisite edges now carry exactly one meaning: the path changed because you struggled. The educational intent was preserved through sequence ordering instead, and the invariant is enforced by schema, prompt, and a regression test.

11 Persistence & resume

The learning session is the durable half of the system — SQLite stores nodes, edges, per-node state, cached lessons and the current pointer.

  • A returning user with the same repo and goal skips the pipeline entirely — no clone, no embedding, no Sonnet call.
  • resume_point() restores where they stopped, respecting recorded weak spots.
  • Lessons are cached on the node, so revisiting a concept is free.
  • doc_context is copied onto the stored graph so real docstrings survive resume.

13 Limitations & next steps

  • LLM nondeterminism — graph shape varies run to run; guardrails are structural, not exact-output.
  • Partial rule firing — the safety-critical ordering rule holds for most, not all, extension points.
  • Single-range anchors — a concept spread across files cannot yet be anchored as one node.
  • Single user, no auth — team-shared graphs are a deliberate non-goal for v1.
  • Next: richer adaptive moves beyond confusion and skip; an AI-Assisted Development Mode where the Grader evaluates a developer's critique of generated code; audio walkthroughs; a VS Code extension.
